# 外网入口、访问控制与公共池

在现有公开 fork 中构建，使用 `main` 作为 AstrBot 安装和更新来源。

## 身份与权限

- `/galgame web` 发送可配置的 HTTP(S) 外网链接；不包含登录密码，不变更隧道。
- 聊天平台用户 ID 和网页用户名是两套身份，各自配置 blacklist/whitelist 模式、黑名单、白名单、管理员列表。
- 黑名单优先于一切，管理员可绕过白名单；网页已有管理员角色仍有效。名单不创建用户、不自动绑定平台 ID 与网页用户。
- 网页登录、已登录 Cookie、API 身份验证同时执行策略，防止仅阻止登录却允许旧会话继续访问。

## 公共池状态与隔离

作者从自己的会话提交不可变的文字快照，状态为 pending。管理员阅读后批准为 approved 或拒绝为 rejected，记录审核人、时间、原因。公开用户只能看到 approved，作者可以看自己的全部状态，管理员可以看全部投稿。

快照仅保存 user/assistant 的文字，不包含语音文件、UMO、会话 ID、系统消息、原账户私人配置。原会话删除不影响快照。作者和管理员可撤回条目；已领取副本不受影响。

领取只能针对 approved：分配新的 session_id、owner、UMO、消息 ID，持久化后在 AstrBot 中创建带有快照历史的新对话。数据库初始化失败则回滚个人会话。这样发送后续消息时模型能够接续记录，同时不会写入他人的会话。

## 交互与限制

独立 WebUI 增加公共池入口；页面含会话选择、投稿标题和简介、公开确认、记录预览、个人投稿、管理员待审核列表、通过/拒绝/撤回和领取按钮。

每条 1–400 条文字消息、最多 100000 字符；标题 1–100 字符、简介及审核意见最多 2000 字符；每账号最多 10 条待审核，总计最多 1000 条记录。公共池 JSON 使用锁和原子替换保存，重启后保持状态。

## 验证

测试策略优先级、平台范围、既有 Cookie 被拉黑、配置管理员权限、投稿归属、未批准不可领取、待审核/拒绝内容不可见、快照清洗、领取独立性、AstrBot 历史注入及失败回滚。检查前端脚本语法和 API 路由白名单覆盖。
